# Wireframes and design archive

This folder preserves design explorations, comparisons and earlier prototype snapshots. They remain useful references even when the current application takes a different direction.

- **Keep these files during documentation cleanup or refactoring.** Age, duplication and lack of links from the current app are not reasons to delete them.
- Delete or replace archived material only when the user explicitly requests it.
- Preserve supporting assets and dependencies with each wireframe. Add new explorations under descriptive, dated names instead of overwriting earlier versions.

The running prototype lives at the project root; archived snapshots may contain older code and data.

Use `YYYY-MM-DD-short-english-description` for top-level files and folders: the documented export/snapshot date, lowercase words and hyphens. Related files share the same stem, such as `.html` and `.zip`. Keep internal asset filenames intact to preserve references.
